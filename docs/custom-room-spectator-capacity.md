# Custom Room spectator and bench admission capacity

Hosts can limit **new neutral spectators and Red/Blue bench members** separately from total room capacity. The native room administration panel offers **0 / 4 / 8 / 16 / 64** spectator slots; the default is 64. The room HUD control summary displays the real server-known number of neutral human participants and the selected limit. When the limit is zero, no additional neutral participant can join. The control is unavailable in human-only Quick Match.

**Server-authoritative preflight:** before adding a new player socket to a room's native client roster, granting owner status, touching match/rematch state or adding a native player disc, RoomCore calculates the newcomer’s actual **assigned team** from the current native roster and the established live-match spectator-admission rules. If assignment is team 0 and existing native connected or reserved human spectators already meet or exceed the current limit, admission fails with a clear message. The check is a single synchronous server-side operation, not a browser-only hint. Bots never count as spectators. Unconnected-but-valid reserved slots still count so a reconnect cannot be displaced; original reserved reconnects follow the existing secure rejoin path rather than allocating a new spectator slot.

The independent **overall** room capacity and bans, Club restrictions, existing sign-in and Quick Match queue, native per-team limits, legitimate solo practice first-challenger exception and explicit Watch-first admission rules remain in force. Host-only `roomAdmin.spectatorLimit` changes admission to one of the five enumerated options; it does **not** eject current people, forcibly change their teams, stop play, revoke an existing ticket, cancel a rematch proposal, replace bots or reset game physics. Lowering the limit below a current neutral population is permitted, so the room fills no more such seats until enough people leave.

The native `roomControl` status announces the supported setting and actual count to current room members. No personal data or room keys are included in this information. A legacy room server does not advertise support, so the client hides the control. The host can continue to admit already connected neutral people to teams using existing fully authorized/consented substitution controls (not changed here).

No change to approved BFF physics, engine tick, AI training/model pointers, ratings, human-only Quick Match, room identifier or spectator-chat security. No manual QA/test/regression suites are added or invoked. Existing mandatory exact-head CI, review/branch protection and authorized VPS release/drain/rollback gates remain intact; GitHub merge is not evidence of live server deployment.
