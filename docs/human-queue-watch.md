# Human Queue Watch · foreground Play view

The native Play → Quick Match panel offers an **opt-in human playlist watch**. Choose 1v1, 2v2, 3v3 or 4v4 and a minimum number of humans genuinely waiting (up to the playlist's required humans minus one), then select **Start watching**. The panel reuses the existing 15-second live occupancy refresh and the existing server's validated /api/quick-match/availability response. The UI shows the last observed human waiting count and time. When the chosen threshold is met, it enables an explicit **Search** button which clicks the original playlist control and therefore preserves authentication, permission checks, actual queue admission and ready-check acceptance. It cannot silently join, switch modes, accept a ready check or substitute bots.

The watch only displays counts for a WebSocket server whose host, protocol and /ws path agree with the website that returned the HTTP snapshot. Cross-origin or manually chosen external servers get no inferred occupancy. Invalid/unavailable snapshots clear the active count; tab invisibility, network offline and server-address changes discard previous evidence. The watch does not persist settings, hold a background connection, create browser notifications or send personal data beyond the existing availability fetch. An occupied queue is **not** a verified available match, ETA, player identity, ranking or win.

The new UI is independently styled, accessible via native button/select focus and polite status announcements, and supports smaller screens. No game physics, bot decision-making, native matchmaking server, account storage, deployed processes, ranked logic or existing mandatory CI workflow is changed.
